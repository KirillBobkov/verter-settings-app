## 1. Резюме

**Что это.** Веб-консоль оператора мобильного робота Verter (ROS на Jetson). Три статические страницы на нативном JS: «Состояние робота» (мониторинг + режимы + ручное управление), «Карта» (SLAM/локализация/точки/маршруты/costmap/сохранение), «История батареи» (графики BMS + экспорт). Приложение размещено на GitHub Pages и общается с роботом напрямую по WebSocket через NATS request/reply — без собственного бэкенда.

**Ключевые факты.**

| Факт | Значение |
|---|---|
| Стек | Нативный JS (IIFE-модули), OpenLayers 10, pako, js-sha256, nats-core 3.4.0; сборки нет (статика) |
| Транспорт | `fetch('/api/*')` → api-shim → NATS request/reply по wss → хаб (VPS) → leaf-соединение робота `verter_01` → Python-bridge → ROS |
| Модель данных | Только поллинг request/reply; подписки (NATS subscribe) не используются |
| Аутентификация | Креды NATS (JWT + NKEY seed) в localStorage; ACL на одного робота |
| Режимы робота | `idle` / `mapping` / `localization` / `navigation` (единый supervisor, переходы только через idle); UI дополнительно отображает `fault` и `unknown` |
| Деплой | GitHub Actions: node --check → Pages. Runtime-конфиг — `config.js` |

**Найденные скрытые дефекты (важно для редизайна):**

1. **Слои costmap не работают на GitHub Pages.** `costmap-ui.js` запрашивает `/api/costmap`, но в `nats-api-core.js → routeGet()` маршрут `/api/costmap` отсутствует — прослойка отвечает `404 Not found`, панель «Слои» вечно показывает «Нет связи с costmap». Нужно добавить subject-маршрут (домен costmap) в ядро или убрать слои из клиентской версии.
2. **Ручное управление мертво на странице карты.** `drive-widget.js:25` подгружает `'/static/drive.js'` (путь оригинального робота). В этом репозитории файл лежит в корне — на Pages скрипт даёт 404, крестовина на карте остаётся в «Проверка связи…».
3. **`camera-link.js` — осиротевший файл**: не подключён ни одной страницей; карточки «Камера/Лидар» на главной скрыты `api-shim.js` (окна живут только на роботе, порты 8089/8090).
4. **OPERATORS.md обещает показ срока действия кредов — не реализовано.** В панели настроек нет парсинга `exp` из JWT (в кабинет оператора добавлено, раздел 8.4).

**Вывод для редизайна.** Функциональное ядро (контракты NATS, логика свежести, сценарии режимов) зрелоe и его надо сохранить как «домен»; презентационный слой собран из трёх несогласованных тем (сине-серые `#101722`, бирюзовые/циановые акценты, белая модалка в `api-shim.js`) и переписывается на единую тёмную систему с лаймовым акцентом `#c8ed00`.

## 2. Контекст продукта

```
GitHub Pages (site/, статика)
   │  wss:443, креды ui-<имя>.creds
   ▼
NATS-хаб (VPS, verter-proxy.duckdns.org)
   ▲  leaf:7422
робот verter_01 (Jetson)
   ├─ nats_bridge (Python): HTTP-зеркало /api/* → subjects, supervisor режимов
   ├─ ROS: SLAM Toolbox, AMCL, Nav2, лидар/IMU/одометрия/УЗ, cmd_vel → шасси
   ├─ BMS по BLE (JK): battery.update.*, история (SQLite), экспорт
   └─ отдельные сервисы: камера (:8089), лидар-окно (:8090) — только в LAN робота
```

Пользователи: **оператор робота** (клиентский контур) и **разработчик/инженер** (дебаг-контур). Роли на уровне NATS ACL пока не разделены — оба работают одними кредами.

### 3.2 Смысловая группировка (для редизайна)

**Контур «Оператор» (клиентский UI — редизайн в первую очередь):**
- B2+B3+B4+B7+B9 — «Пульт дежурства»: что робот делает, здоров ли, переключить режим, подвезти вручную, оставить заметку.
- B5+B6 — «Карта-мастерская»: построить карту, сохранить, натянуть локализацию, разметить точки/маршруты, посмотреть препятствия.
- B8 — «Энергия»: история и отчётность по батарее.

**Контур «Инженер» (дебаг/мониторинг — сохранить, спрятать за режимом):**
- B10 (диагностика на главной), диагностические блоки страницы карты (`map-diagnostics`, `scan-quality`, параметры карты, счётчики costmap), панель ⚙ NATS, полная JSON-простыня, subjects-словарь.
- Внешние LAN-окна камеры/лидара (скрыты на Pages, живут на роботе).

**Платформенный контур (не виден пользователю, не менять без нужды):**
- B1 на уровне транспорта, `nats-api-core.js` (маршруты/таймауты/конверты), `api-shim.js` (перехват fetch, экспорт батареи), `config.js`, деплой.

**Правило редизайна:** клиентский контур перерисовываем; инженерный — сохраняем функциональность, помещаем в явный «инженерный режим» (отдельный раздел/переключатель); платформенный — не трогаем (он проверен на живом хабе).

### 3.3 Пользовательские сценарии (top-5)

1. **Утренний обход:** открыть сайт → увидеть режим/батарею/датчики → оставить заметку. (B2, B7, B9)
2. **Построить карту:** mapping → гонять робота крестовиной → карта в окне карты → сохранить с именем → подтверждить выход через discard. (B3, B4, B5, B6-сохранение)
3. **Поставить робота на карту:** idle → выбрать карту → локализация → указать начальную позу → визуально сверить → подтвердить. (B6-локализация)
4. **Разметить зону:** точки + маршрут (порядок точек) — подготовка к будущему запуску. (B6-точки/маршруты)
5. **Отчёт по батарее:** неделя → графики → скачать CSV. (B8)
6. **Первый вход / истечение кредов:** вставить креды, подключиться; за 3 дня до `exp` — заменить (полная спецификация — раздел 8.1). (B1)

## 4. Как работает приложение (архитектор)

### 4.1 Слои и совместимость

Оригинальные страницы писаны под HTTP `web.py` робота. Прослоека делает их транспорт-агностичными:

```
app.js / map.js / localization-ui.js / costmap-ui.js / battery-history.js / drive.js
        │ fetch('/api/...')                      ← код страниц не менялся
        ▼
api-shim.js   — перехват window.fetch для '/api/*'
        │ POST /api/command → routeAction(action) → subject
        │ GET  /api/...     → routeGet(path)      → subject
        ▼
nats-api-core.js — конверты {v:1,id,issued_at,ttl_s,args}, таймауты
        │ nc.request(subject, JSON, {timeout})
        ▼
lib/nats-core.iife.js (@nats-io/nats-core) — wsconnect + credsAuthenticator
        ▼
wss://verter-proxy.duckdns.org → робот (leaf) → Python bridge → ROS
```

Ключевые решения:
- **Синхронизация часов.** Каждая страница держит `serverClock = {at, midpoint}` из поля `at` любого ответа (образцы принимаются при RTT < 800 мс в drive.js, < 1000 мс в остальных); `issued_at` команд считается как `at + (now − midpoint)`. Для cmd_vel (TTL=1 c) `issued_at` обязан быть **дробным** — на практике из `serverNow()` (серверные часы, дробные); `Date.now()/1000` — только fallback в app.js, для cmd_vel синхронизация обязательна (без образца моложе 5 с команды не отправляются). Иначе floor съедает секунду и запрос отклоняется как expired (проверено на живом хабе).
- **Таймауты прослойки чуть меньше клиентских AbortSignal**, чтобы робот успел ответить ошибкой раньше тишины: service 9.5 c, map 5 c, map.save 9.5 c, battery.history 20 c, cmd_vel 1.1 c, страница экспорта 15 c/страницу.
- **Ответ 503** при timeout/no-responders с текстом «outcome unknown — проверьте состояние перед повтором» — изменяющие команды **никогда не повторяются автоматически** (id-дедупликация на бэкенде).

### 4.3 Карта поллинга (нагрузка одной страницы карты)

| Модуль | Интервал | Запрос |
|---|---|---|
| map.js | 1 c | metadata (+diagnostics — второй запрос каждый тик) |
| map.js | 200 мс | pose |
| map.js | 200 мс | scan |
| localization-ui | 1.5 c | metrics + localization.get (2 запроса за тик) |
| costmap-ui | 500 мс | costmap state (сейчас 404) |
| drive-widget | 250 мс | cmd_vel.status |
| map-shell | 500 мс | локальный перерендер |
| timers map.js | 500 мс | локальная проверка свежести |

Итого **≈17–18 NATS-запросов/с** при активной странице карты (1+1+5+5+~1.3+4); вкладка в фоне останавливает поллинг (`document.hidden` во всех модулях), а при возврате — `visibilitychange` сбрасывает pose/scan/снапшоты в «неизвестно» и делает внеочередной поллинг. **Вывод:** при редизайне сохранить дисциплину `document.hidden` и busy-флаги (единый PollScheduler); в среднесрочной перспективе — переход на NATS-подписки (`map.update.*`, `battery.update.*`, `service.update.*`, `cmd_vel.update.target` — все существуют в контракте; KV watch доставляет начальный набор, конец — событие `None`; публикации и KV-записи не атомарны — согласованную батарею брать из `battery.snapshot`), оставив request/reply для команд.

### 4.4 Модель «свежести» (повторять в новом UI обязательно)

Единый паттерн по всему коду: значение валидно, если
`connected && age_s + локальный_дрейф ≤ max_age && map_id/revision/session совпадают && quality ok && !stale`.
Контракт требует проверять **оба** `sample_at` и `updated_at` против `max_age_s`; время заметно из будущего (допуск >2 с) — невалидно. Возраст считается на момент отрисовки (перерендер раз в 0.5–1 с), а не только на момент ответа. Конкретные пороги: карта — stale при возрасте метаданных >3,5 с; поза/скан — >1,5 с; локализация — окно свежести 4,5 с, поза ≤2 с; батарея — >8 с; «нет связи, но есть снимок» = показать последнее с пометкой stale. `quality`: `ok` ≠ физическая точность; `stale` = прежнее измерение с истёкшей свежестью; `unavailable` = не получено (обычно `value:null`); отсутствие значения = `null`, не ноль — в UI отображать «—», не 0. Любой редизайн обязан сохранять: явные состояния «свежие данные / устаревшие (показано последнее) / нет данных» и подсказки-причины в `title`/тексте (сейчас это `modeReason`, `confirmationReason`, `contextHint`, `unavailableReason`, словарь reason-кодов локализации `waiting_for_current_session_amcl_pose` и др. — ценнейшая логика, переносится как есть).

### 4.5 Безопасность и многопользовательность

- Креды (JWT+seed) только в localStorage браузера (ключи `verter.ui.creds` / `verter.ui.natsWsUrl`); на хабе ACL scoped на `verter_01.*` + KV-read. Кнопка «Забыть» удаляет креды и override адреса (сейчас — сразу, без подтверждения; confirm в кабинете — новое поведение).
- Ручное управление: одна активная сессия на робота (`session_id`+`seq`, lease 1 с, watchdog); чужая сессия блокирует стрелки (СТОП остаётся доступен, но без свежих часов и его команда вернёт ошибку синхронизации); завершённый `session_id` блокируется на 60 с, новое управление — всегда новый UUID. При скрытии вкладки/blur — авто-стоп; **pagehide стоп НЕ отправляет** (только локальный сброс флага — при обрыве останавливает серверный lease-watchdog). После ошибки/потери связи автоматического возобновления нет.
- Флаги робота: `allow_mode_changes` (смена режимов) **и `allow_manual_motion` (крестовина, по умолчанию false; ошибка `manual_motion_disabled`)** — UI обязан блокировать движение с подсказкой-причиной, как это сделано для режимов. Выход из mapping требует `discard=true`.
- Обязательные тексты безопасности (из OPERATORS/контрактов): «Стоп — программная команда, не аппаратный аварийный выключатель», «Ручное управление не включает автоматический объезд препятствий (Nav2)», «Отпускание стрелки не останавливает робота», «Никому не пересылайте файл кредов: он даёт управление роботом».
- Изменяющие команды — через `window.confirm()` (не модернизировать в редизайне без замены на кастомную модалку с теми же текстами-причинами). Таймаут/потеря ответа ≠ «не исполнено»: сначала прочитать состояние, не повторять команду (дедупликация по id; `outcome_unknown_after_interruption_inspect_state`).

## 8. План «Личного кабинета оператора» (готов к переписыванию)

### 8.1 Назначение и сценарии

Кабинет = страница самообслуживания оператора: подключение, учётные данные, персональные настройки, прозрачность доступа. Сценарии: (1) первый вход — вставить креды и подключиться; (2) креды истекают — увидеть срок и заранее обновить; (3) сменить робота/хаб; (4) настроить поведение UI под себя; (5) понять, «а кем я вообще подключён».

### 8.3 Композиция — Mobile (<720)

Один вертикальный стек, секции-аккордеоны: **Оператор** (сжатая карточка) → **Подключение** (статус крупно, ping) → **Креды** (полоса срока + 2 кнопки во всю ширину) → **Интерфейс** (переключатели) → **Журнал** (последние 20 записей). Модалка ввода кредов — bottom-sheet на весь экран с моноширинным textarea и валидацией блоков JWT/SEED (текущая проверка из `api-shim.js` сохраняется).

### 8.4 Спецификация данных и поведения (для верстальщика)

| Элемент | Источник | Состояния | Действия |
|---|---|---|---|
| Имя оператора | **(новое)** `sub`/`name` из JWT-части кредов (base64url-декод payload, без верификации — только отображение; сейчас JWT нигде не декодируется) | есть / нет → «Оператор» | — |
| Срок действия кредов | **(новое)** `exp` из того же payload (дефект №4) | >7 дней: нейтрально; ≤3 дней: `--warning` + баннер «запросите новые» (правило из OPERATORS.md); истёк: `--helper-red` | клик → модалка обновления |
| Полоса срока | progress от `iat` к `exp` | — | — |
| Хаб | `localStorage verter.ui.natsWsUrl` иначе `config.js` | override помечен «не по умолчанию» | изменить → reconnect |
| Робот | `config.js robotId` (пока read-only, задел под мультиробота) | — | выбор из списка (future) |
| Статус связи | статус-машина api-shim (idle/connecting/connected/reconnecting/error) | цвет точки: серый/жёлтый/зелёный/жёлтый/красный | — |
| Ping | команда `ping`, RTT | кнопка disabled пока нет связи | вывод «· N мс» |
| Обновить креды | textarea + валидация: **сейчас только два маркера** (`BEGIN NATS USER JWT`, `USER NKEY SEED` — как в api-shim.js); **длина seed 56 — новое правило**; пустое поле кредов НЕ перезаписывает сохранённые (сценарий «сменить только хаб») | ошибка → красный текст | сохранить → reconnect → запись в журнал |
| «Хранить только в сессии» | `sessionStorage` вместо `localStorage` (новое; потребует синхронизировать текст OPERATORS.md «хранятся только в localStorage») | чекбокс, по умолчанию выкл | — |
| Забыть | очистка ключей + close соединения | **confirm-модалка — новое** (сейчас удаляет сразу, без подтверждения) | — |
| Журнал | **(всё новое)** локальный ring-buffer (localStorage, ≤100 записей): подключения, изменяющие команды, экспорт, ошибки; креды в журнал не писать, маскировать | пусто → подсказка | очистить |
| Звук/автообновление/другие prefs | **(всё новое; единственный существующий преференс — локальный чекбокс автообновления на странице истории)** localStorage prefs | — | применяются на других страницах через событие `verter:prefs` |

Границы: кабинет **не** меняет ACL и не знает о других роботах; всё локальное, кроме ping. Креды никогда не отображаются целиком (маска `SU… last4`).

### 8.5 Приёмочные критерии кабинета

1. Новый оператор проходит путь «открыл сайт → вставил креды → подключился» за 3 шага без понимания NATS.
2. За 3 дня до `exp` кабинет и TopBar показывают предупреждение; после `exp` — красный статус и запрет попыток подключения (сразу понятная ошибка вместо таймаутов).
3. Все текущие возможности панели ⚙ сохранены (валидация, forget, override адреса).
4. Mobile 360px: все действия доступны без горизонтального скролла; textarea удобна для вставки из менеджера паролей.
5. `window.VerterCreds.snapshot()` для e2e (по аналогии с существующими хуками).

### 9.2 Что нельзя сломать (инварианты)

1. `nats-api-core.js` — таймауты, дробный `issued_at` для cmd_vel, конверты v1 (зеркало web.py), реконнект-параметры, `module.exports`.
2. Логика свежести/причин блокировок (`modeReason`, `confirmationReason`, `activeScope`, `mapState`, словарь reason-кодов локализации…) — переносится дословно, включая проверку обоих `sample_at`/`updated_at` и допуск «из будущего».
3. Дисциплина: ничего не отправлять при загрузке/поллинге; авто-стоп при уходе вкладки (pagehide — только локальный сброс, стоп гарантирует серверный lease); никакого автоповтора изменяющих команд; таймаут ≠ «не исполнено» — сначала прочитать состояние; epoch/generation-защита drive (старый poll не отменяет новое нажатие).
4. Подтверждения с полным текстом последствий (нулевую скорость может послать завершение **любого** режима supervisor, не только mapping; «цель движения этим действием не задаётся»; снятие прежнего подтверждения локализации).
5. Snapshot-хуки (`VerterDashboard`/`VerterCostmaps`/`VerterMapTools` — снапшот-функции) **и `VerterMap` — живые объекты** (`ol.Map`, `ol.View`, `getMetadata`, `getState`) — на них завязаны e2e и межмодульная связь; переносить форму доступа, не только имена.
6. Доступность: tablist-паттерн вкладок (roving tabindex + ArrowLeft/Right/Home/End), `role="status"` на статусных строках (13+ мест — при потере атрибута анонсы молча исчезают), `aria-live` результаты, aria-keyshortcuts, фокусируемая drive-панель (tabindex=0 + делегирование keydown + возврат фокуса по pointerdown — это НЕ фокус-ловушка), aria-label канв графиков, `<meter>` с aria-label.
7. **Внутренние события карты**: `verter:map-state` (map.js → map-shell), `verter:map-saved` (map.js → localization-ui: обновление списка карт), `verter:map-tool-change` (map-shell → отмена placement) — контракт связки модулей, при разбиении «по блокам» не потерять.
8. **Drive-семантика «защёлки»**: отпускание кнопки не останавливает; автоповтор клавиши игнорируется; модификаторы Alt/Ctrl/Meta/Shift отключают управление; Space на сфокусированной кнопке движения = stop; фокус сам по себе команд не отправляет; `session_id` блокируется 60 с после stop, новое управление — новый UUID.
9. **Совместимость контракта**: игнорировать неизвестные поля/метрики, отклонять неизвестную `v`; отсутствие значения = `null` (в UI «—», не 0); `flags_raw`/неизвестные биты не преобразовывать в аварии; малая ковариация AMCL не доказывает правильное положение (подтверждение только визуальное).
10. Клавиатурная защита от дублирования клика и стилей: data-relevant-подчёркивание вкладок, `.moving` по одометрии (не по команде), `.old-data` обесцвечивание батареи, `[hidden]{display:none!important}`, `:empty→display:none`, min-width:0 в сетках, overflow-wrap:anywhere, devicePixelRatio-рендер canvas графиков, touch-action (manipulation/pan-y).
11. **Мобильный функциональный паритет**: ни одна функция не скрывается и не удаляется брейкпоинтом — брейкпоинты меняют только компоновку, плотность и точку входа (перенос в шит/«Ещё»/аккордеон допустим, сокрытие — нет). Приёмка каждой фазы — по чек-листу 6.3 на 360×740.

### B.3 P1 — сценарии и функционал (все ✏ внесены или 📋 учтены)

- Межблокировка: активная ручная сессия блокирует смену режимов (`manual_control.active` → modeReason).
- Автосброс `discard` при смене scope сессии; фиксация `initialization_id` до refreshState (защита от гонки подтверждения).
- Загрузка списка карт из двух источников (schema + `part=saved`, фильтр `grid!==false`) с частичным/полным отказом и авто-выбором активной карты.
- visibilitychange карты: сброс pose/scan в «неизвестно» + внеочередной поллинг; costmap `pageEpoch` с полной очисткой.
- «Сохранить текущее положение» — только при `verified===true`+freshPose (`source:'current'`); запрет удаления точки, используемой в маршрутах (с перечнем маршрутов в ошибке).
- `loadCatalogs`: token-защита гонок, кросс-проверка `map_revision` waypoint/route, очистка drafts при смене ревизии.
- Follow-поведение: pointerdrag и «Вся карта» снимают «Следовать»; новая сессия карты → авто-fit; map-shell `automaticChoice` (mapping→«Сохранение», иначе→«Локализация»).
- Гонка сохранения заметки («предыдущий текст сохранён…»), фокус-guard ввода.
- Кабинет: показ причины ошибки подключения («хаб отклонил origin» — `allowed_origins`); сценарий «сменить только хаб» (пустые креды не перезаписывают).
- Межстраничная интеграция: `verter:map-saved` → обновление списка карт + сообщения об успехе/отказе обновления.

### B.4 P2 — информация и детали (реестр для верстальщика)
