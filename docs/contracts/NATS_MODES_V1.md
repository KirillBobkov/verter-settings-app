# Единое управление режимами через NATS

Все ROS-режимы принадлежат `verter-supervisor` (`tools/runtime.py`).
CLI `tools/verter` и NATS bridge обращаются к одному Unix socket `run/control.sock`.
Bridge не запускает и не завершает ROS-процессы самостоятельно. Его перезапуск
не останавливает режим supervisor. Режим, запущенный из CLI, виден через NATS/KV.

## Команда

Subject: `<robot_id>.service.command.mode_set`, action для HTTP: `mode.set`.
Общий конверт v1 с UUID, issued_at, ttl_s и args. NATS не передаёт поле action.

```json
{
  "v": 1,
  "id": "db8d27f7-5faa-4ab6-b3dc-c75551fc8303",
  "issued_at": 1793001600,
  "ttl_s": 30,
  "args": {"mode": "mapping"}
}
```

Время и UUID примера необходимо заменить; пример не является разрешением запуска.

Режимы:

- `idle`: завершить текущий режим supervisor, сохранив hardware/voice/web.
- `mapping`: существующий launch SLAM Toolbox и map saver из verter_bringup.
- `localization`: только map_server, AMCL и lifecycle manager, без контроллера движения; обязателен map.
- `navigation`: полный Nav2 с AMCL; обязателен map.
  Принимается ID из конфигурации maps либо имя сохранённой карты в data/maps.
  Произвольный путь от клиента не принимается.

`localization` — самостоятельный launch. Готовность AMCL не требует заданной начальной позы.
Инициализация, подтверждение, точки и маршруты описаны в [LOCALIZATION_API_V1.md](LOCALIZATION_API_V1.md).
Для перехода между активными режимами сначала перейти в idle.
Выход из mapping требует сохранения карты оператором и явного `discard=true`:
текущий supervisor не ведёт флаг «карта сохранена». Без discard выход запрещён.
Сохранение доступно через map.save в вебе/NATS либо tools/verter save-map.

Локальный `allow_mode_changes` разрешает изменяющие запросы NATS, но не наблюдение.
По умолчанию нового установщика он false. При недоступном supervisor изменяющая
команда отвергается. Активная ручная сессия NATS также блокирует смену режима.
Для запуска проверяются свежесть ROS graph и отсутствие конфликтующих SLAM/Nav2
нод вне режима supervisor; датчики и lifecycle readiness проверяет сам supervisor.
Наличие издателя esp32_ctrl не блокирует запуск SLAM: издатель не доказывает движение.
Правило одного источника управления сохраняется, автоматического арбитра здесь нет.

## Принятие и завершение

Ответ `{v,id,ok:true,at,result}` подтверждает принятие операции, а не готовность ROS.
`result.operation.id` равен id запроса, status сначала `running`.
Подтверждение готовности приходит в `service.mode` (KV и update subject):

```json
{
  "owner": "supervisor",
  "actual": "mapping",
  "desired": "mapping",
  "stale": false,
  "operation": {
    "id": "db8d27f7-5faa-4ab6-b3dc-c75551fc8303",
    "status": "succeeded",
    "requested_mode": "mapping",
    "requested_at": 1793001600,
    "finished_at": 1793001604,
    "error": null
  }
}
```

Operation status: running/succeeded/failed. Одновременно допускается одна операция.
При ошибке смотреть operation.error и actual; при тайм-ауте исход операции может
быть неизвестен, требуется повторно прочитать состояние, а не создавать новый запуск.
Повтор того же UUID и конверта возвращает исходное подтверждение принятия из
журнала команд. Итог смотреть по состоянию, не по повторному ответу.
TTL ограничивает принятие запроса; принятая операция может выполняться дольше TTL.

Наблюдение supervisor обновляется примерно раз в 2 секунды. Во время изменения
режима socket занят ожиданием readiness; bridge сохраняет последнее actual,
показывает desired/operation и выставляет stale после 8 секунд без наблюдения.
`stale=true` означает, что actual не является подтверждённым текущим режимом.
При отсутствии первого ответа actual=`unknown`. `started_at=null`, поскольку
supervisor не передаёт точное время старта. `localization_verified=false` —
положение робота на карте требует самостоятельной проверки оператором.

Bridge не восстанавливает принятые операции запуском процессов после своего
перезапуска: он заново читает действительный режим supervisor. Operation —
текущее состояние работы адаптера, не долговременный журнал задач.

## Ограничения управления

Запуск картографирования не отправляет команд скорости. Существующий путь
завершения режима supervisor может публиковать нулевую скорость; навигационный
режим способен выполнять задания, когда их задаёт оператор. Такие действия
нельзя использовать как пассивную проверку. Тесты используют подменённый Unix
supervisor и отдельный NATS, ROS отключён. Для установки новой реализации режима localization требуется обновить bringup и
перезапустить supervisor, чтобы он загрузил новый runtime.py. Это отдельное согласованное действие,
поскольку остановка существующего режима может отправить нулевую скорость.
